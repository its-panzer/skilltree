# Release checklist

Fictional example for the Skilltree framework.

Read the proposed change and the target environment. Scale the checklist to the actual release rather than copying a universal deployment ritual.

## Readiness decisions

Identify what must be true before rollout, what proves success afterward, and how to stop or recover if the behavior is wrong. Include data migrations and dependency ordering only when this release needs them.

## Deliverable

Separate completed checks from remaining work. Name the evidence for each completed item. Make the next action concrete. A checklist is not authorization to deploy or publish unless the user has requested that action.
